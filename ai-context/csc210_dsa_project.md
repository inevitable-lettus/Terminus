Garv's CSC210 "Intro to DSA" course group project is **Project #3: Smart Public Bus Route Planning and Passenger Information System**, chosen from a course-provided list of project options (other options included Agri Marketplace, Water Complaint Monitoring, Dairy Collection, Heritage Tourism, Lost & Found, Skill Exchange, Disaster Relief Coordination).

**Project #3 spec (from course project list PDF):**
- Motivation: students use GSRTC, AMTS, BRTS and city buses regularly.
- Users: Passengers, Conductors, Administrators.
- Features: bus search, route optimization, seat availability, delay prediction, route analytics, schedule management.
- DSA focus: Graph, Heap, Queue, Hash Table, Algorithms, Dijkstra, BFS, A*, Sorting.
- Required research component: compare shortest-path algorithms across different network sizes.

**Course workflow (7 stages, per course infographic "DSA Group Project Journey"):** Explore & Plan → Design → Implement → Test & Optimize → Deploy → Document → Evaluate & Reflect. Course expects: appropriate DSA concept usage, a usable real-world system, documentation/testing/evaluation, and reflection.

**Course-suggested example tech stack:** React (frontend), Node.js/Express (backend), PostgreSQL/MongoDB (database), JWT & RBAC (auth), Git/GitHub (version control), Render/Railway/Vercel (deploy).

**Why this matters:** the course's suggested stack (Node/Express) differs from Garv's usual stack (Next.js + FastAPI/Python) — worth flagging if he defaults to FastAPI for this course project, since the course materials assume Node/Express, though nothing stops using Python if he prefers and can justify it.

**How to apply:** when helping with this project, ground algorithm/DSA choices in the required focus list (Graph, Heap, Queue, Hash Table, Dijkstra, BFS, A*, Sorting) and keep the required shortest-path-algorithm-comparison research component in scope for deliverables/docs.
